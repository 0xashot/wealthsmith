# Protocol Handoff Checklist

Use this checklist whenever implementing or reviewing WealthSmith protocol handoffs, external protocol CTAs, Manage links, protocol routing, protocol decisions, protocol copy, protocol analytics, or Smith AI explanations of protocol destinations.

This checklist protects the MVP boundary:

```text
Protocol Logic decides where.
UI renders the handoff.
Smith AI explains the handoff.
MVP handoffs are review-only.
```

# 1. Core Protocol Boundary

## 1.1 Responsibility separation

- [ ] Protocol Logic decides protocol destination.
- [ ] Suggestion Engine decides whether a suggestion exists.
- [ ] Top Pick Logic decides whether the suggestion is Top Pick.
- [ ] UI renders protocol decision state.
- [ ] Components render passed protocol decision props/state.
- [ ] Smith AI explains protocol decision.
- [ ] UI does not choose protocol.
- [ ] UI does not choose protocol URL.
- [ ] UI does not rank protocols.
- [ ] UI does not choose protocol based on icon, APY, or local fallback.
- [ ] Smith AI does not choose protocol.
- [ ] Smith AI does not invent protocol URL.

Critical failure:

```text
UI, component code, or Smith AI chooses, changes, ranks, or invents protocol destination or URL.
```

---

## 1.2 MVP handoff boundary

In MVP, protocol handoffs are:

```text
external
review-only
user-initiated
non-custodial
non-executing
```

Checklist:

- [ ] Handoff opens an external protocol page.
- [ ] Handoff opens in a new tab.
- [ ] Handoff does not execute a transaction.
- [ ] Handoff does not request wallet signature.
- [ ] Handoff does not move funds.
- [ ] Handoff does not submit a swap.
- [ ] Handoff does not stake.
- [ ] Handoff does not deposit.
- [ ] Handoff does not withdraw.
- [ ] Handoff does not rebalance.
- [ ] Handoff does not mark suggestion complete on click.

Critical failure:

```text
MVP protocol handoff executes, signs, moves funds, submits, deposits, withdraws, rebalances, or marks completion.
```

- [ ] Protocol decision has destination protocol ID.

- [ ] Protocol decision has approved destination URL.
- [ ] Protocol decision has handoff type.
- [ ] Protocol decision has CTA label.

# 4. Protocol Eligibility

## 4.1 Eligibility source

- [ ] Protocol eligibility comes from Protocol Logic.
- [ ] UI does not determine eligibility locally.
- [ ] Smith AI does not determine eligibility.
- [ ] Eligibility considers supported asset.
- [ ] Eligibility considers supported action.
- [ ] Eligibility considers supported protocol.
- [ ] Eligibility considers guardrails.
- [ ] Eligibility considers stale data.
- [ ] Eligibility considers locked/blocked states.
- [ ] Eligibility considers Safety Buffer priority when relevant.

High failure:

```text
UI enables protocol handoff when Protocol Logic marks it ineligible, stale, locked, blocked, or unavailable.
```

---

## 4.2 Guardrails

Protocol handoff must respect guardrails such as:

```text
minimum trade size
cost threshold
liquidity validity
slippage threshold
supported asset
supported action
supported protocol
Safety Buffer preservation
fresh data
```

Checklist:

- [ ] Guardrail results come from product/protocol logic.
- [ ] Failed guardrails block active protocol handoff.
- [ ] Failed guardrail reason is visible when relevant.
- [ ] UI does not bypass guardrails.
- [ ] Smith AI does not bypass guardrails.
- [ ] Protocol CTA is disabled/blocked when required guardrail fails.

Critical failure:

```text
Protocol handoff remains active despite failed required guardrail.
```

# 6. Handoff Behavior

## 6.1 External new tab

- [ ] CTA opens external protocol in a new tab.
- [ ] App state remains unchanged after opening external tab.
- [ ] Suggestion is not marked complete on click.
- [ ] Top Pick is not cleared on click.
- [ ] Portfolio values are not changed on click.
- [ ] Wallet state is not changed on click.
- [ ] User can return to WealthSmith with state preserved.
- [ ] External link clearly indicates new-tab behavior.

Critical failure:

```text
Clicking external handoff mutates app state as if user completed the action.
```

---

## 6.2 No execution

- [ ] Handoff click does not call transaction-building code.
- [ ] Handoff click does not request wallet signature.
- [ ] Handoff click does not submit swap.
- [ ] Handoff click does not submit stake transaction.
- [ ] Handoff click does not submit deposit transaction.
- [ ] Handoff click does not submit withdraw transaction.
- [ ] Handoff click does not submit rebalance transaction.
- [ ] Handoff click does not show transaction success toast.
- [ ] Handoff click does not show funds moved message.
- [ ] Handoff click does not trigger portfolio update as completed action.

```text
Handoff click triggers any transaction-like behavior.
```

